# نظام ناصيه – NASIAH

تطبيق ويب داخلي بواجهة بيضاء عصرية ومستقلة لإدارة شيتات العقارات الخاصة بخمسة Team Leaders مع حسابين Admin.

## التشغيل على Windows
1. ثبّت Node.js إصدار LTS.
2. فك ضغط الملف.
3. افتح مجلد المشروع في VS Code.
4. افتح Terminal داخل المجلد وشغّل:
   ```bash
   npm install
   npm start
   ```
5. افتح المتصفح على: http://localhost:3000

## الصلاحيات
- الأدمن يشاهد ويضيف ويعدل ويحذف في كل الشيتات.
- كل Team Leader يرى الشيتات الخمسة، ويضيف ويعدل ويحذف في شيت حسابه فقط.
- الخادم يتحقق من الصلاحيات، وليس الواجهة فقط.
- ملخص القطاعات محمي على مستوى API للأدمن فقط.
- يمكن للأدمن تنزيل نسخة احتياطية Excel من زر الإدارة؛ تحتوي على ورقة ملخص وورقة مستقلة لكل Team Leader.
- حسابات المستخدمين الجديدة مطالبة بتغيير كلمة المرور عند أول تسجيل دخول، ولا يمكن إغلاق نافذة الإلزام قبل التغيير.

## قاعدة البيانات والنسخ الاحتياطي
- مجلد `data` يُنشأ تلقائياً، وقاعدة البيانات تنشأ في `data/inventory.sqlite` عند أول تشغيل.
- أوقف السيرفر قبل نسخ ملف قاعدة البيانات احتياطياً.
- لا تحذف مجلد `data` عند تحديث ملفات البرنامج حتى لا تفقد البيانات.

## النشر والاستضافة
- يدعم التطبيق SQLite محلياً وPostgreSQL عند ضبط `DATABASE_URL`.
- التطبيق خادم Express مستمر ويخدم الواجهة وAPI من نفس الخدمة؛ يستخدم `/healthz` لفحص جاهزية التطبيق واتصاله بقاعدة البيانات.
- يمكن نشره كـ Docker service على Northflank وربطه بقاعدة Neon PostgreSQL. تعرض صفحة Northflank حالياً خطة مجانية تشمل حتى خدمتين وموردات بقيمة تصل إلى 20 دولاراً شهرياً؛ الأسعار والحدود قابلة للتغيير، لذا اضبط تنبيهات الاستخدام وتحقق من شروط الخطة قبل النشر: https://northflank.com/pricing
- أنشئ قاعدة PostgreSQL مجانية في Neon، وانسخ connection string. لا تضعه في الملفات أو GitHub.
- من PowerShell شغّل السكربت التالي، ثم الصق pooled connection string من Neon عند الطلب. تُقرأ القيمة كإدخال مخفي ولا تُحفظ في الملف أو Git:
  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  .\scripts\migrate-neon.ps1
  ```
  يقتصر تجاوز سياسة تشغيل السكربت على نافذة PowerShell الحالية.
  يتوقف الترحيل إذا لم تكن قاعدة Neon فارغة. ينقل الحسابات والعقارات، ولا ينقل جلسات الدخول. يطلب من حسابات Admin تغيير كلمة المرور عند أول دخول.
- أنشئ خدمة من المستودع الخاص على Northflank، واختر البناء من `Dockerfile` في جذر المستودع. اجعل منفذ HTTP هو `3000` ومسار فحص الصحة `/healthz`.
- أضف `DATABASE_URL` في إعدادات الخدمة كـ Secret باستخدام pooled connection string من Neon. أدخل السر مباشرة في لوحة Northflank، لا في Chat أو ملف داخل المستودع.
- لا تضبط `INITIAL_ADMIN_USERNAME` أو `INITIAL_ADMIN_PASSWORD` عند نقل قاعدة البيانات؛ الحسابات موجودة في Neon بعد الترحيل. لا تحذف مشروع Vercel أو قاعدة Neon، ولا توقف النسخة الحالية حتى تعمل الخدمة الجديدة وتتحقق من تسجيل الدخول والبيانات.
- لا ترفع `data/` أو `.env` أو `seed-accounts.json` إلى GitHub. هذه المسارات مستثناة في `.gitignore`. تجنب إضافة معلومات العملاء إلى أي مستودع.
- استخدم مستودعاً خاصاً، HTTPS، كلمات مرور قوية وفريدة، ونسخاً احتياطياً دورياً. الرابط العام للتطبيق يتطلب تسجيل الدخول للبيانات؛ قاعدة Neon لا تكون متاحة إلا عبر اتصال TLS باستخدام السر الخاص المخزن في إعدادات الاستضافة.
